# 开发计划（Roadmap）

> 原则：**每个版本都可独立使用**；小步发版，tag + CHANGELOG；不提前建空包。
> 估算按 1 名开发者、熟悉代码库计算。

## 0. 当前状态

- 最新版本：**v0.3.0**
- 可用功能：和弦库、音阶指板、40 关游戏（计时 / 判定 / 结果）、进度与星级、逐关解锁、
  严格拼写设置、键盘操作、移动端 40px 点按
- 下一版：**v0.3.1**（每日挑战与统计）

## 1. 版本路线

### v0.3.0 — 可日常练习（已发布）

**目标**：从“能玩一关”变成“每天愿意打开”。

| 优先级 | 任务 | 状态 | 说明 |
|---|---|---|---|
| P0 | 进度模型 | ✅ | `progress: { [levelId]: { completed, stars, bestMs, attempts, lastAt } }`，`guitar.progress.v1` |
| P0 | 星级与解锁 | ✅ | 按用时 + 错误给 1–3 星；1 星解锁下一关 |
| P0 | 结果页升级 | ✅ | 星级、最快全对、三星目标、新纪录/解锁徽章、错误分布、“下一关” |
| P0 | 设置项 | ✅ | 严格拼写开关；重置进度 |
| P1 | 关卡选择 | ✅ | 显示星级/锁；按章分组 |
| P1 | 手机竖屏 | ✅ | 375px 实测无横向溢出；点按 ≥ 40px；指板内部滚动 |
| P1 | 键盘操作 | ✅ | Tab 选格、Enter 开选择器、字母输入音名（可加 #/b）、方向键选择、Esc 关闭 |

**实现**：`progress.ts`（星级/达标时间/解锁/迁移/本次得星，纯函数）+ 键盘音名输入
（`nextNoteQuery`/`noteCandidates`）+ 15 个新单测；`lib/storage.ts`（含旧键迁移）；
`Stars` 组件；游戏页结果面板、设置与键盘操作。

**遗留（不阻塞发布，进 v0.3.1 看情况）**：375px 只确认了「无横向溢出」，
逐个按钮的点按尺寸与 iOS Safari 聚焦缩放（控件字号 < 16px 会放大页面）未逐一验证；
指板横滑时弦名列会跟着滚出视野。

**验收**：
- 40 关可连续玩，刷新后进度、星级、最佳都在；
- 未解锁关卡不可进入；
- 375px 宽无横向溢出（指板内部滚动除外）；
- `pnpm test` 通过，新增 progress 单测。

**不做**：账号、云同步、音频。

### v0.3.1 — 每日挑战与统计（3–5 天）

| 任务 | 说明 |
|---|---|
| 每日挑战 | 日期做 seed，所有人同题；独立最佳 |
| 连续天数 | 当天完成每日挑战 +1 |
| 统计页 | 总关卡、平均星级、总用时、最近 7 天 |
| 分享文案 | 复制“我在 Guitar Lab 完成 L12，用时 1:23” |

**验收**：同一天不同设备 seed 一致；统计数字与 progress 一致。

### v0.4.0 — DSH 插件（约 1 周）

**前置**：给 core 加构建（`tsup`，CJS + ESM + d.ts），供插件与未来小程序使用。

| 任务 | 说明 |
|---|---|
| Host 工具 | `guitar.generatePuzzle`、`guitar.lookupChord`、`guitar.explainAnswer` |
| Client 面板 | 复用 `Fretboard`，做和弦/音阶速查 + 每日一题 |
| 主题/locale | 继承 `--dsw-alias-*`，文案走 locale service |
| 安装 | `plugin_manager install_bundle`，验证 slot 渲染 |

**验收**：插件安装后侧栏可用；工具可被 agent 调用；卸载无残留。

**注意**：DSH 插件是“伴生”，不是主形态；不允许 iframe。

### v0.5.0 — 桌面 / 安卓壳（1–2 周）

| 任务 | 说明 |

### v1.0.0 — 稳定版（约 2 周）

- 新手引导（3 步：选调 → 填一格 → 提交）
- 40 关难度复核（真实用户数据）
- 错误边界、离线提示、版本号展示
- CI（GitHub Actions：test + build）
- 性能：首屏 < 1s（本地）

**验收**：新用户 5 分钟内完成第一关；无 P0/P1 bug；文档与 CHANGELOG 完整。

## 2. 暂不排期（Backlog）

| 项 | 触发条件 | 备注 |
|---|---|---|
| 微信小程序 | 微信成为主渠道 / 需要分享裂变 | 原生 UI + core CJS；8–10 人日 + ICP 1–2 周 |
| 账号 / 云同步 / 排行榜 | 有跨设备需求 | 需后端与隐私合规 |
| iOS | 有明确用户群 | Capacitor 可复用 |
| 曲谱 / 播放 | 产品扩展到“跟谱” | 与当前定位不同，单独立项 |

## 3. 风险

| 风险 | 影响 | 对策 |
|---|---|---|
| 音乐理论错误 | 教学错误，信任受损 | core 单测覆盖拼写/出题；新增调先加测试 |
| 内容量不足 | 40 关玩完即走 | v0.3.1 每日挑战 + 后续扩展关卡 |
| 音频时序 | 节拍器不可用 | 用 AudioContext 时钟，不用 setInterval 累加 |
| 多端维护 | 版本分叉 | core 唯一真相；UI 适配层隔离 |
| 审核/备案（小程序） | 上线延期 | 启动前先办 |

## 4. 完成定义（DoD）

一个任务算完成，需要：

- 代码 + 类型检查通过；
- 相关测试通过（core 逻辑必须有测试）；
- 文档更新（规则/交互有变时）；
- `CHANGELOG.md` 有记录；
- 版本号与 tag（发版时）；
- 在浏览器实际点过（UI 任务）。

## 5. 发版流程

见 `versioning.md`：改版本号 → 更新 CHANGELOG → commit → annotated tag → push。
